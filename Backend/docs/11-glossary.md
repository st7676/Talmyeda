# מילון מונחים

מונחים שחוזרים בקוד ובתיעוד, מוסברים בקצרה למי שפחות מכיר.

## תשתית ופיתוח

**Node.js** — סביבת ריצה ש-JavaScript יכול לרוץ בה מחוץ לדפדפן (על שרת).

**TypeScript** — "JavaScript עם טיפוסים". מתקמפל ל-JavaScript רגיל, אבל
בזמן הכתיבה בודק שאתה לא מנסה, למשל, לחבר מספר עם אובייקט בטעות. תופס
המון באגים **לפני** שהקוד בכלל רץ.

**NestJS** — framework ל-Node.js שמארגן קוד למודולים עם Dependency
Injection מובנה (ראו `01-how-it-works.md`). דומה ברוח ל-Angular (אותו
צוות פיתח את שניהם), אבל לצד שרת (backend) במקום דפדפן.

**MongoDB** — מסד נתונים "NoSQL" (לא-יחסי). שומר "מסמכים" (documents)
בפורמט דמוי-JSON במקום שורות בטבלה. גמיש יותר מ-SQL כשאין סכימה קבועה
מראש — מתאים לפרויקט הזה כי כל מוסד מגדיר שדות שונים.

**Mongoose** — ספרייה שמוסיפה סכימות (schemas), ולידציה, ואינדקסים
מעל MongoDB — כי MongoDB "הגולמי" לא אוכף שום מבנה בעצמו.

**ORM / ODM** — "Object-Relational/Document Mapper" — קטגוריית כלים
כמו Mongoose, שממירה בין אובייקטים בקוד (מחלקות TypeScript) לבין רשומות
במסד נתונים.

## Docker (ראו הסבר מורחב בשיחה — סיכום כאן)

**Docker** — כלי ש"עוטף" אפליקציה יחד עם כל מה שהיא צריכה (גרסת Node,
ספריות, הגדרות) לחבילה סגורה שרצה **אותו דבר בדיוק** בכל מחשב.

**Image (תמונה)** — "מתכון קפוא" — קובץ סטטי עם כל מה שצריך כדי להריץ
את האפליקציה. **לא** רץ בעצמו.

**Container (מיכל)** — image **שרץ בפועל** — תהליך מבודד עם מערכת קבצים
ורשת משלו, אבל משתמש ב-kernel של המחשב המארח (קל משקל בהרבה ממחשב וירטואלי).

**Dockerfile** — קובץ הוראות שלב-אחר-שלב לבניית image (`FROM`, `COPY`,
`RUN`, `CMD` וכו').

**docker-compose.yml** — קובץ שמתאר איך **כמה** containers (למשל: שרת +
MongoDB) עובדים ביחד, מחוברים לאותה רשת פנימית. `docker compose up`
מרים את כולם בפקודה אחת.

**Volume** — תיקייה על המחשב האמיתי שמוצמדת ל-container, כדי שדאטה
(כמו קבצי MongoDB) לא תיעלם כשה-container נסגר.

## מונחי NestJS ספציפיים

**Decorator** — "תיוג" מיוחד שמתחיל ב-`@` (למשל `@Injectable()`,
`@Controller()`, `@Roles(...)`). מוסיף מטא-דאטה או התנהגות למחלקה/מתודה/
פרמטר בלי לשנות את הקוד "הרגיל".

**Module (`@Module()`)** — יחידת ארגון ב-NestJS: מקבץ controllers,
providers (services), ומגדיר imports/exports למודולים אחרים.

**Controller** — מחלקה שמגדירה HTTP routes (`@Get()`, `@Post()` וכו').
אמורה להיות "דקה" — רק לקבל בקשה ולהעביר ל-service, בלי לוגיקה עסקית.

**Service / Provider** — מחלקה עם `@Injectable()` שמכילה את הלוגיקה
העסקית האמיתית. "מוזרקת" (injected) לתוך controllers/services אחרים.

**DTO (Data Transfer Object)** — מחלקה שמתארת **מה מותר** לשלוח ב-בקשה
(שדות + ולידציה). NestJS ממיר את גוף הבקשה (JSON) לאובייקט מהמחלקה הזו
ובודק אותו לפני שהקוד שלנו בכלל רואה אותו.

**Guard** — קוד שרץ **לפני** ה-controller ומחליט "מותר/אסור" (מחזיר
`true`/`false`, או זורק שגיאה).

**Interceptor** — קוד שרץ **לפני וגם אחרי** ה-controller — יכול לשנות
גם קלט וגם פלט.

**Pipe** — קוד שמבצע טרנספורמציה/ולידציה על פרמטרים נכנסים (למשל,
`ValidationPipe` שממיר ומאמת גוף בקשה מול DTO).

**Filter (Exception Filter)** — תופס שגיאות שנזרקות ומחליט איך להגיב
ללקוח.

## מונחי אימות ואבטחה

**JWT (JSON Web Token)** — "כרטיס כניסה" חתום דיגיטלית שהשרת נותן
לקליינט אחרי login מוצלח. מכיל מידע (payload) שאפשר לפענח (לא סודי!)
אבל **לא ניתן לזייף** בלי לדעת את המפתח הסודי של השרת. הקליינט שולח אותו
בחזרה בכל בקשה (ב-header `Authorization: Bearer <token>`).

**bcrypt** — אלגוריתם hashing לסיסמאות. הופך סיסמה גולמית למחרוזת
מוצפנת חד-כיוונית (אי אפשר "לפענח" hash בחזרה לסיסמה) — כך שגם אם ה-DB
נגנב, הסיסמאות עצמן לא נחשפות.

**Hash (גיבוב)** — פונקציה שממירה קלט (כמו סיסמה) לפלט קבוע-אורך שנראה
אקראי, ולעולם לא ניתנת "להיפוך" חזרה למקור.

**ABAC (Attribute-Based Access Control)** — מודל הרשאות שמחליט לפי
**תכונות** (של המשתמש, של הישות, של ההקשר) ולא רק לפי תפקיד קבוע —
ראו `06-casl-permissions.md`.

**CASL** — ספריית JavaScript ליישום ABAC (`@casl/ability`) — בשימוש
במודול `casl/` של הפרויקט.

## מונחי מסד נתונים

**Schema (סכימה)** — הגדרת המבנה של מסמך (אילו שדות, אילו טיפוסים,
אילו אילוצים).

**Document (מסמך)** — רשומה בודדת ב-MongoDB (שקול ל"שורה" ב-SQL).

**Collection (אוסף)** — קבוצת מסמכים מאותו סוג (שקול ל"טבלה" ב-SQL).

**Index (אינדקס)** — מבנה נתונים פנימי שמאיץ חיפוש לפי שדה מסוים —
בלי אינדקס, MongoDB סורק כל מסמך כדי למצוא התאמה.

**Aggregation Pipeline** — סדרת שלבי עיבוד (`$match`, `$sort`, `$group`
וכו') שמאפשרת שאילתות מורכבות שלא אפשריות עם `.find()` רגיל — בשימוש
כאן למיון לפי שדה דינמי (ראו `07-participants-staff-groups.md`).

**Soft Delete (מחיקה רכה)** — במקום למחוק רשומה פיזית, מסמנים אותה
`isDeleted:true` ומסתירים אותה משאילתות רגילות. שומר היסטוריה ומאפשר
שחזור.

**Multi-Tenant (רב-דיירות)** — ארכיטקטורה שבה מערכת אחת (ומסד נתונים
אחד) משרתת כמה "דיירים" (tenants — כאן: מוסדות) נפרדים, כשכל אחד רואה
רק את הדאטה שלו.
